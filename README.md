# Olist E-Commerce Data Cleaning & ETL Pipeline

A Python pipeline that takes the raw Olist Brazilian e-commerce CSV files, cleans them, joins them into one analysis-ready table, and loads everything into a SQLite database.

## Problem
Raw data comes in many separate files that are not ready for analysis. Before anyone can answer questions about sales or deliveries, the data has to be cleaned, checked and joined. This project automates that process so it can be re-run on new data.

## Dataset
[Olist Brazilian E-Commerce Public Dataset (Kaggle)](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce): 9 CSV files covering customers, orders, order items, products, sellers, payments, reviews, geolocation and a category translation table (about 1.6 million rows in total).

## Tools
Python (pandas), SQLite, SQL

## How the pipeline works
1. **Extract:** read the 9 raw CSV files from `data/raw/`.
2. **Transform:**
   - collapse repeated rows (geolocation) and check every table for duplicate keys
   - convert 5 order date columns from text to real dates
   - standardise text (city names, state codes, order status, payment type)
   - handle missing values and invalid rows (missing categories, missing delivery dates, zero-value and undefined payments)
   - add new columns: delivery days, delay days, late-delivery flag, purchase month
   - join the tables into one table, `sales_fact` (one row per order item)
3. **Load:** write all cleaned tables and `sales_fact` into `output/olist.db`, and write `output/data_quality_report.md`.
4. **Validate:** automatic checks that no order ID is empty, no order item is duplicated, all prices are above 0, and every row has a purchase date and customer state. All 5 checks passed.

## Results
- `sales_fact` has **112,650 rows**, one for each order item, with no rows lost in the joins.
- **Geolocation:** 1,000,163 rows reduced to **19,015**, one per zip-code prefix (981,148 repeated rows removed).
- **Products:** 610 products had no category and were labelled "unknown"; 13 had a category with no English translation and kept their original name.
- **Orders:** 8 orders marked as delivered had no delivery date; I kept them and left the date empty rather than inventing one.
- **Payments:** removed 3 rows with payment type "not_defined" and 6 rows with zero payment value.
- The other tables had no duplicate keys, no invalid prices and no out-of-range review scores.

The full list is in `data_quality_report.md`, generated by the pipeline.

## Example findings from the SQL queries
- Revenue from delivered orders peaked in November 2017 (about 988K), with April and May 2018 close behind (about 974K and 978K).
- health_beauty was the top category by revenue (about 1.23M), followed by watches_gifts (about 1.17M) and bed_bath_table (about 1.02M).
- Items per order differ a lot by category: watches_gifts earned its revenue from only 5,859 items (about 199 per item), while bed_bath_table sold the most items (10,953) at about 93 per item.

## Project structure
```
explore.py               first look at the raw data
etl_pipeline.py          the pipeline (extract, transform, load, validate)
queries.sql              data checks and business questions
data/raw/                raw CSV files (not included, download from Kaggle)
output/                  database and data quality report (created by the pipeline)
```

## How to run
```bash
pip install -r requirements.txt
# download the Olist dataset from Kaggle and put the 9 CSV files in data/raw/
python explore.py
python etl_pipeline.py
```
Then open `output/olist.db` with DB Browser for SQLite and run `queries.sql`.

## What I learned
The real data was mostly clean: most tables had no duplicate keys or invalid values. The biggest problem was the geolocation table, which had over 980,000 repeated rows for the same zip codes, so I collapsed it to one row per zip prefix. I kept the 8 delivered orders with no delivery date and left the date empty instead of guessing one. Next I would add automated tests and run the pipeline on a schedule.
